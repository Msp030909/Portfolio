Reflection


The Highlight

My favourite project out of all the ones I've worked on would definitely be Super Duper Platformer. I already have some godot knowledge before starting the project, but doing this really helped me learn how to use it well. For example, focusing on things like composition made me able to achieve things much more easily, and do things that had made me drop previous projects because I just didn't know how to do them. It's here that I got a hang of GDScript, that I figured out how to use more advanced techniques like get/setting variables, consistently making timers using code, using export variables to their full potential, and more.


The Process

What I've learned is that once you learn the fundamentals, making a game with Godot becomes a very fun task as you think about the best ways to implement the mechanics you want to have. Making this game was really my first time experimenting with component systems, export variables, and more, and having to figure it all out from the spot really forces you to think. Doing it successfully also feels super rewarding, especially when you have something that you can now re-use over and over again. I'm able to look at tutorials when needed, but I feel like I am at a point with godot where I can figure out these systems on my own, which is my preferred way of learning. I also feel like I have a much better understanding of how to use the engine, and how to structure my projects, which is something that I struggled with before.


The Friction

I can't really think of anything to put here. That's not to say there weren't troubles making it or the project, but it's more like everything I did was in the very least fun to make. The reason I like Godot, and programming languages, really, is because of this learning process. That being said, for Super Duper Platformer specifically, I don't really recall struggling with many things. I guess the NPC dialogue system was hard to make, but to be fair, that was one of the first things I made, so I assume I got better later on as things went. It was interesting using export variables for the first time, and trying to transfer everything from the npc to the hud and make the dialogue display, and so on, but after that, I think I got used to it. I don't recall struggling much with the attackComponents (although I did have to retroactively add them in for the earlier goomba-type enemies after creating the stronger sword enemy), and I might have struggled making the sword aiming function work, if I hadn't already done something similar in a previous project, with the help of someone more skilled than I am at Godot. Overall, it was a really fun experience, and it ended up surprisingly well too. I managed to end it ahead of schedule, which is a pretty rare thing, to be honest!


Context and AI

To be honest, I've found I don't really like using AI in my work. It's fun to brainstorm and vibecode a little something here and there, sure, but every time I do so I feel like I can't really be proud of the project, because after all, I didn't really make that, did I? Maybe it's because I'm still in a beginning level and I know that when I use it, I'm not really learning as much as I would if I actually tried making it. Regardless, for the HTML minigame projects, I tried to at least have some human input put into it. Whenever I asked the ai to do something, e.g make a platformer, I would ask it to make it in a way where I can easily access and modify things like parts of the level, enemy positions, and where the end point is. For my godot game, I chose to not add any AI-generated content, and I think that was the right choice for me. I had a lot of fun making it, and I feel like I learned a lot, and I'm really proud of it, which is the most important thing to me when it comes to projects like this. I don't think using AI is inherently bad, but for me personally, I prefer to do things on my own, and I feel like I learn more that way too.


The Agentic Loop

I've talked about the learning loop before, but I don't mind talking about it again. The agentic loop was something I went through a LOT while making Super Duper Platformer. I think that not only is it an effective way of learning, but it's satisfying, and you get a real sense of accomplishment when you finally figure out how to do something that you had no idea how to do before. I think that the key to making the most out of the agentic loop is to really embrace the struggle, and not be afraid of it. My main method, for example, was doing things my way as far as I could possibly go, and then when I got stuck, I would search it up and try to find a tutorial or part of the documentation that could help me. However, one thing I really wanted to make sure was that I really understood what was going on. Something I saw a lot of other people struggled with was overreliance on tutorials. They would follow one almost completely for their game, and then be left wondering extremely simple things like how to remove comments or change a variable. I'm past this level now, but this can definitely still happen if I were to try using higher level code. I think the key is to keep breaking it down more and more; If I go find a tutorial, and I find a built in function I don't recognize, for example, I go and I search up the function, and then read the documentation, find a tutorial that specifically goes over what the function does, and if I still don't understand it, I try and use something like AI overview to make it a little more digestible for me. But overall, I think the key is just to remember that no matter what happens, there are resources available for almost every situation. If you can't find something, it's probably because you're thinking about it too specifically. It might be hard to find a video on "how to make a sword aiming function in godot", but if you search up "how to rotate an object towards the mouse in godot", you'll probably find something that can be easily adapted to your situation. Learning how to do things well is also a factor here. Things like composition vs inheritance are very important to learn.


Next Steps

The original question is what I would do if I had two more weeks and an unlimited budget to continue working on the game. With just two weeks, it's a little hard to answer. Truly, what I want to do is rewrite the game from scratch, but I'm not sure I could get that anywhere near done in two weeks. Instead, I might opt for trying to add a more hollow-knight style enemy. I've been thinking this over in my head for some time already, and I think I could make enemies with specific attack patterns using a lot of Area2Ds. Simply put, if the enemy node contains an animationPlayer, and lots of area2Ds checking if the player is at a specific area, I could put the enemy in an animation where the Area2Ds are disabled and it then does an attack on the exact range of the Area2D the player stepped on. It might get a little complicated if there are many attacks, but it could definitely be done. Given I'd have to implement this into my current game, I would probably make a separate level with him as one big bossfight, with him maybe also spawning minions alongside this. There are some other features that could arguably make the game better, like powerups of some sort, a dash, and so on, but I don't really want to add them to this version of the game in particular. Everything already added has been made with the base player movement and balance in mind, and I don't know if going back and changing all of that or keeping it as is and risking ruining the balance of the game and making it too easy to be fun is a good idea. In kind of a weird way, I think the limitations of the player kind of make the current state of the game and especially the pvp more interesting. They say limitation breeds creativity, and for something like arena mode, since the controls are so simple, I think it has an interesting effect on the skill floor and ceilling. The game is easy to play, but this means those who try and get good at it can find lots of areas to improve their technique in the game (e.g because there isn't a very big way to move quickly, the spacing between players becomes a more important aspect. Trying to find the ideal spot to hurt someone while making it hard for them to hit you is difficult, but it's something many people have figured out for other games).
